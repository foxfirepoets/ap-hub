## What ralph will build

A single TypeScript service that reads accounting email from Gmail, extracts invoice/receipt/statement data with LLM vision, resolves it against QuickBooks Online reference lists, produces a PROPOSED transaction (Phase 1, zero QBO writes), then creates real transactions in a QBO SANDBOX company only (Phase 2, idempotent + verified). It never writes to production QuickBooks. Amendment A1 (2026-07-11): every document is independently verified through the operator's own SwarmSync proof platform — Verify-API checks each LLM extraction, InvoiceProof fraud-scans each invoice before it can qualify for posting, and AuditProof chain-anchors the audit trail and every sandbox posting. No proposal can reach `ready` without both proof calls completed. Phase 0.5 (2026-07-11, CHUNK_4): a proof-gated forwarding relay ("gatekeeper") that InvoiceProof-scans each incoming invoice and auto-forwards only clean ones to QuickBooks' native email-capture address; anything suspicious is HELD + Telegram-alerted. The gatekeeper's locked-down forward is the ONLY email the system can ever send. WHITE-LABEL: the whole build installs into any business by configuration only (env/tenant rows) — no per-business code, proven by the white_label_install test.

Chunks (8 total):
- CHUNK_1_INFRA: Stand up the service skeleton, Postgres schema/migrations (incl. proof_refs + forwards), pg-boss queue, typed config, and the SwarmSync HTTP client.
- CHUNK_2_AUTH: Implement encrypted OAuth for Gmail-readonly plus QBO read-only with confirm-realm.
- CHUNK_3_INGEST: Poll Gmail incrementally, persist deduped messages, download and hash attachments.
- CHUNK_4_GATEKEEPER: InvoiceProof-scan every ingested invoice; auto-forward clean ones to the QBO capture address (single-recipient lockdown); hold + Telegram-alert everything else (Phase 0.5).
- CHUNK_5_EXTRACT: Classify documents, extract structured invoice fields via LLM vision with confidence, and verify each extraction through Verify-API.
- CHUNK_6_MAPPING: Import QBO lists, resolve mappings, InvoiceProof-scan every invoice, emit proposed transactions (completes Phase 1).
- CHUNK_7_POSTING: Create idempotent, verified QBO sandbox transactions from proof-gated proposals, each anchored via AuditProof (Phase 2).
- CHUNK_8_HARDENING: Complete the exception taxonomy, audit logging + daily audit anchor, CLI, and validation test suite.

## Prerequisites

- Node.js 20 + TypeScript
- PostgreSQL (local via `docker compose up -d db`, or Supabase/Neon)
- npm
- Vitest (test runner)
- Anthropic API key (LLM vision)
- Gmail OAuth app (readonly scope; the CHUNK_4 gatekeeper adds `gmail.send` for its locked-down relay) + QuickBooks Online **sandbox** app
- SwarmSync API key (`ssk_live_…`, from the Verify-API dashboard at swarmsync.ai) — Amendment A1
- Phase 0.5 gatekeeper: the company's QBO capture address (…@qbodocs.com — the SENDING Gmail address must be registered to a user on that QBO company; check Settings → Receipt forwarding) + a Telegram bot token & chat id for hold alerts

## Setup Before First Run

1. Install dependencies: `npm install`
2. Copy environment file: `cp .env.example .env`
3. Fill in all required variables in `.env` (see AGENTS.md / .env.example). Keep `QBO_ENV=sandbox`.
4. Start the database: `docker compose up -d db`
5. Run migrations: `npm run migrate:up`

## Start ralph

```bash
while :; do cat PROMPT.md | claude; done
```

ralph starts in PLANNING mode (PROMPT.md == PROMPT_plan.md).
After it emits `<promise>PLANNING COMPLETE</promise>`, swap to build mode:
`cp PROMPT_build.md PROMPT.md`
Then restart the loop.

## When ralph gets stuck

1. Check `.ralph/errors.log` for the failure pattern.
2. Add a guardrail to `.ralph/guardrails.md` so ralph avoids it.
3. Fix the specific broken file manually if needed.
4. Update `.ralph/state.md` to point at the stuck task.
5. Restart the loop.

## Chunk Completion

`<promise>CHUNK COMPLETE: CHUNK_N_DOMAIN</promise>` → progress logged, ralph advances. No manual step needed unless errors.

## Build Complete

`<promise>BUILD COMPLETE</promise>` → run the gate once more: `npm run lint && npm run typecheck && npm test`, then `npm run test:int` against sandbox, then review `.ralph/progress.md`.

## The Six Guarantees ralph Must Never Break

1. **Nothing before CHUNK_7 writes to QBO, and Gmail is never modified** — no QBO write code exists before CHUNK_7 (absent, not disabled); no labels, no replies. Proven by the `no_write` test. (Amendment A1: calls to the operator's own SwarmSync proof platform are permitted and required — they never touch the books or the mailbox.)
2. **The only email the system can EVER send is the gatekeeper's forward, and it can only address the tenant's configured QBO capture address** — the send wrapper has no recipient parameter. Proven by `send_lockdown`.
3. **Phase 2 (CHUNK_7) writes ONLY to the QBO sandbox** — no production write path exists; `QBO_ENV=production` is hard-refused. Proven by `no_prod_write`.
4. **No create ever double-posts, and no invoice is ever double-forwarded** — two-layer dedup + replay-adopt-on-timeout on both paths. Proven by `idempotent_double_post`, `replay_after_timeout`, and `no_double_forward`.
5. **Nothing unscanned gets through** — no proposal reaches `ready`, nothing posts (even sandbox), and nothing is forwarded to QBO capture without completed proof coverage; every gatekeeper hold raises a Telegram alert; SwarmSync outage degrades to review-only/hold, never blocks, never fail-opens. Proven by `proof_refs_recorded`, `proof_fail_safe`, `proof_gate_posting`, `gatekeeper_hold`, `unscannable_hold`, `held_alert`.
6. **White-label: a new business installs by configuration only** — no tenant-specific value in code. Proven by `white_label_install`.
