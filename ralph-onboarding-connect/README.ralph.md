## What ralph will build

Wires ap-hub's already-built-but-disconnected Gmail/QuickBooks OAuth exchange logic into the
onboarding wizard: real "Connect" buttons, a cross-process signed CSRF state token, a fixed
dev-port collision, and a collapsed wizard UI where the user does ~2 real actions and everything
else (company confirmation, dry-run, automation-off default) happens automatically.

Chunks (5 total):
- CHUNK_1_STATETOKEN: signed, time-boxed CSRF state token for the connect flow
- CHUNK_2_REDIRECT: redirect capability in the plain HTTP server; wire signed state + redirect into the OAuth callbacks
- CHUNK_3_CONFIG: fix the port collision between the pipeline HTTP server and Next.js
- CHUNK_4_STARTROUTES: session-gated Next.js routes that redirect into the real OAuth consent flow
- CHUNK_5_PAGEREDESIGN: collapse the wizard to one "Connect your accounts" screen; auto-complete the rest; final gate

## Prerequisites

- Node 20+, npm
- Next.js App Router (existing ap-hub `app/` tree) + the existing plain Node HTTP server (`src/http.ts`)
- PostgreSQL reachable at `DATABASE_URL` (existing ap-hub DB — this feature adds no schema)
- Real Gmail/QBO OAuth app credentials for true end-to-end manual verification (NOT available in
  this sandbox — see the spec's §14 Known Limitations; automated gates cover the code paths, not
  a live provider round-trip)

## Setup Before First Run

1. Install dependencies (already installed in ap-hub repo root): `npm install`
2. No new env vars — ap-hub's existing `.env` already has everything needed; if `PORT`/
   `GMAIL_REDIRECT_URI`/`QBO_SANDBOX_REDIRECT_URI` are set explicitly there (not just defaulted),
   update them to the new port (3001) after CHUNK_3 lands.
3. Verify database is running: `export DATABASE_URL=postgres://aphub:aphub@127.0.0.1:5432/aphub`
4. Run migrations (expect "No pending migrations" — this feature adds none): `npm run migrate:up`
5. Confirm baseline green before starting: `npm run lint && npm run typecheck && npm test && npm run web:build`

```bash
#   ~\.claude\skills\ralph-wiggum-loop\scripts\ralph-loop.ps1 -Auto -MaxIterations 20
```

**In-session mode (used for this build):** run build iterations inside Claude Code — Claude acts
as ORCHESTRATOR and spawns one fresh subagent per chunk via the Agent tool (sequentially), using
these same state files, then independently re-runs the validation gate before committing (never
trusting a subagent's self-report — especially important here given the real security surface).
NEVER run `claude` or the loop scripts through Claude Code's Bash tool — that nests a Claude
session inside a Claude session.

## When ralph gets stuck

1. Check `.ralph/errors.log` for the failure pattern.
2. Add a guardrail to `.ralph/guardrails.md` so ralph avoids the same pattern.
3. Fix the specific broken file manually if needed.
4. Update `.ralph/state.md` to point at the stuck task.
5. Restart the loop.
